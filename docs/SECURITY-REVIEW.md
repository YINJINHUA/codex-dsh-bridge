## 已有实机证据能说明什么

此前开发包已验证两端官方profile安装、正常启动、插件开关和只读状态查询；也有两端实际发信回信证据。它们说明路线可行，不证明当前候选的全部平台/权限组合已通过。

Windows 最近的三级测试实际完成了 3→2→1 回信，但创建调用超时返回 `creation_unknown_no_retry`，故整轮不能判为通过。CLI 首轮工具输出/进程完成异常根因尚未确定，不能直接归咎权限或网络，不能换编号重建。

## 本轮重点回归

- 新旧登记的状态目录重叠拦截，拒绝时不进入 DSH 会话操作。
- Mac Allow ACL及缓存失效；拒绝不安全目录，不改系统ACL。
- 强制并发调度验证回执发布，避免读取空/半截JSON，且不覆盖已有记录。
- direct创建路径参数校验、安全错误码和连接异常隔离。
- 原有去重、撤销、取消、大小/超时限制、Host/Worker和平台专属用例。
- Windows独占新建/替换文件的属主与受保护DACL、重复写入不覆盖、临时文件清理；拒绝边界测试仅改变合成对象的DACL，不要求审计权限。

## 尚存限制

- Windows早期本地全套曾超时；后续0.3.7云端全套通过，但耗时较长，不代表所有机器均具备相同稳定性。保留原时限和安全门，Windows继续标为预览。
- Windows深层状态目录存在长路径限制：本轮262字符回执路径发布失败，缩短测试目录至151字符后同项通过。优先默认状态位置，见[Windows说明](WINDOWS.md)；未通过修改全局长路径策略掩盖限制。
- 项目登记不是调用者认证；有同用户权限的进程可能读写配置或调用端点。本机配置的程序只检查路径/文件权限，不鉴定它来自官方发行方。
- DSH full-access仍为同一状态目录范围的全局覆盖，默认inherit；本次未改策略范围。已有会话权限不会因更新、撤回配置或卸载而改变。
- Codex queue正文经过argv，同用户可观察；不要发送秘密或敏感用户正文。
- CLI创建的exec会话不保证侧栏可见；日常请已有Codex对话使用桌面原生能力创建。
- Windows受限沙箱访问工具/桥状态、共享目录初始化及高级CLI创建仍有未解决的组合问题，详见 [Windows](WINDOWS.md)。
- Linux仅模式位/属主检查，未增加通用ACL探测；真实断电、长时间压力及所有宿主版本组合未验证。
- `queued_only`不是完成；结果窗口不完整会返回null；未知交付必须人工核查。定向发布检查和测试均不是“无漏洞”证明。
