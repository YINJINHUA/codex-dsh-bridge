修补包含异常响应分类、回包排空关闭、标题控制字符校验、请求身份核对和实际打包清单校验。Windows 单机测试文件并发上限为2；原安全检查、断言和时限保持，云端仍按三个独立分组运行。

源码卫生门禁检查公开文件清单、版本一致性、必要入口和常见敏感信息模式；打包门禁检查实际文件清单、大小、缺失/额外/重复文件和入口。它们不是完整安全审计或“没有漏洞”的保证。发布候选补充文档时另核与实测包的差异，运行代码和测试字节须一致。

0.4.1 的本机验证已完成，准确提交的 GitHub CI 和 npm 发布仍须按[发布流程](RELEASING.md)核验；不把本机通过当作云端通过或已发布。

## 实机协作链路

验证使用合成任务 `17 × 19 = 323`：由协调对话创建执行对话，再创建独立审查对话，分别写产物并回传。独立审查复算和核对产物哈希；这验证交接流程，不等于对桥插件代码进行了一次独立安全审查。

- **macOS：** 首轮完成 xsession 执行与独立审查交接，报告实际进入 Codex。修补候选另验证 inherit 创建、普通发送及实际回传；两轮证据分别保留，不混称为同一包的全链重复执行。未加载的 Codex 接收者经正常原生流程准备后，核到独立桥消息，未重发。
- **Windows：** 修补候选完成协调对话创建、执行和审查两阶段 xsession 实际交接，两份报告均进入既有 Codex 接收者并得到回复。匹配请求编号、发送与接收会话、消息编号、产物及哈希，未仅根据 accepted 判定成功。
- **权限：** 两平台执行和审查对话使用显式 inherit，实际核到 workspace-write；Windows 同时核到 ask 审批策略。协调对话的完全权限没有复制给执行或审查对话。创建回执的 verified=false 本身不作为权限证明。
- **取证缺口：** Windows 执行回传的测试脚本曾因输入与输出文件名仅大小写不同而丢失子命令退出码；实际送达由持久化回执和 Codex 原生入站另行证实，没有重发补日志。审查阶段改用不同文件名，回传退出码与实际入站均已核验。

本轮复用既有 Codex 接收对话，没有再次验证通过 CLI 新建 Codex 对话，也未覆盖所有忙闲切换、跨电脑或跨项目组合。配套插件的收件箱和去重索引只在其运行期间保留，不能当作永久已读回执，见[配套指南](XSESSION.md)。

## 仍需注意的边界

- Windows 保持预览标记。CLI 创建 Codex 对话曾在实际创建或回信后返回结果不明；后续单次通过不消除该风险，也不保证侧栏可见。优先由已有 Codex 对话使用桌面原生能力创建。
- queued_only 只表示入队；最近结果可能属于旧回合，或因有界窗口而返回 null。未知交付须按原编号核查，不换编号、清记录或改变路线自动重试。
- Windows 深层状态目录存在长路径限制；受限沙箱访问工具、桥状态及共享目录也有未覆盖的组合。采用默认私有状态位置，保留 ACL 检查，见[Windows说明](WINDOWS.md)。
- 项目登记是路由核对，不是调用者认证。本机同用户进程可能读写配置或调用端点；程序路径与权限校验不等同于发行方签名验证。
- DSH full-access 配置作用于同一桥状态目录下的已登记项目，默认 inherit；已有会话权限不会因撤回配置、更新或卸载而改变。
- Codex queue 正文经过 argv，同用户可能观察；不发送凭据或敏感用户正文。
- Linux 未实机验证，仍只核模式位和属主，没有通用 ACL 检查。真实断电、长期压力及所有宿主版本组合未验证。

## 历史结果

0.4.0 发布提交 `fada184` 已通过八项 CI，并正式发布到 npm latest。此前 Windows 创建结果不明、系统检查超时和状态 ACL 异常的记录保留于维护者本机审计资料，不以新版通过覆盖旧失败。

Windows 性能优化曾在相同机器及测试入口下，将一轮全套耗时从约557秒降至231秒；0.3.8与后续提交的云端测试也曾从约12分钟降至约7分钟。测试数量、并行安排和主机负载随后有变化，这些历史数据不是0.4.1或其他机器的耗时承诺。当前R2的Windows本机106项完整回归约10分钟。
